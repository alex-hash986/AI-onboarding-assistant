# Руководство администратора и HR

Руководство описывает, как адаптировать Buddy AI под структуру компании, обновлять базу знаний (БЗ) и проверять ответы после публикации. HR и владельцы процессов подтверждают факты, контакты и регламенты. Администратор обновляет подключённые файлы и проверяет стенд.

## Где хранятся знания

| Файл | Содержимое |
| --- | --- |
| `docs/company_profile.md` | Паспорт компании: график, структура отделов, общие правила, инструменты и порядок обращений. |
| `knowledge_base/departments_and_contacts.csv` | Ответственные, контакты, темы эскалации, резервные каналы и SLA. |
| `knowledge_base/processes_and_faq.csv` | Вопросы новичков и подтверждённые процедуры. |
| `knowledge_base/tools_setup_guides.csv` | Инструкции по корпоративному ПО и действия при отсутствии доступа. |
| `knowledge_base/onboarding_checklists.csv` | Задачи адаптации и этапы их выполнения. |

В каждой таблице у строк есть уникальные `id`. При изменении существующей записи сохраняйте её `id`, для новой выделяйте свободный по схеме таблицы. Системный промпт в `prompts/system_prompt.md` задаёт формат ответа и протокол эскалации.

## Добавление отдела или смена ответственного

1. Согласуйте с владельцем процесса название отдела, перечень тем, ответственного, контакты и SLA первого ответа. Определите, куда направлять сотрудника при недоступности Битрикс24.
2. В `knowledge_base/departments_and_contacts.csv` добавьте запись для нового отдела или исправьте существующую при смене ответственного.

   | Поле | Что заполнить |
   | --- | --- |
   | `id` | Уникальный стабильный идентификатор записи. |
   | `department` | Согласованное название отдела. |
   | `responsible_person` | Полное ФИО ответственного. |
   | `role` | Должность или роль ответственного. |
   | `email` | Подтверждённый рабочий адрес. |
   | `telegram` | Подтверждённый рабочий ник с `@`. |
   | `sla_hours` | Число рабочих часов до первого ответа, например `4`. |
   | `escalation_topics` | Темы, по которым отдел принимает обращения. |
   | `alternative_channel` | Подтверждённый резервный канал при недоступности основного. |
   | `notes` | Условия маршрутизации и служебные примечания, в том числе демонстрационный статус контакта при необходимости. |

3. В `docs/company_profile.md`, раздел «Отделы и контакты», обновите строку отдела. Сверьте название, ФИО, роль, почту, Telegram, SLA и темы с CSV. Если изменился сам порядок обращений, обновите его описание в паспорте. При переносе темы между отделами синхронизируйте оба маршрута и обновите правила в `prompts/system_prompt.md`, если распределение ответственности там указано явно.
4. После загрузки файлов задайте вопрос по новой или изменённой теме. Проверьте основной маршрут через Битрикс24 и повторите запрос с уточнением, что портал недоступен. Сверьте отдел, ФИО, контакты, резервный маршрут и SLA. Для нового отдела проверьте также близкую по смыслу тему, которая осталась у другого владельца.

## Актуализация материалов

Обновляйте БЗ при изменении контакта, регламента, инструмента или задач адаптации. Периодичность плановой сверки согласуйте с владельцами материалов. Перед публикацией владелец проверяет новые сведения, а администратор сверяет связанные записи между файлами.

- В `processes_and_faq.csv` добавьте типовой вопрос и утверждённый ответ. Укажите, к кому применяется процедура, её шаги, сроки и маршрут для исключений.
- В `tools_setup_guides.csv` добавьте инструкцию по ПО. Укажите необходимые доступы, порядок настройки и контакт для случаев, когда сотрудник не может выполнить шаг самостоятельно.
- В `onboarding_checklists.csv` добавьте конкретную задачу на нужный этап адаптации. Опишите ожидаемый результат и укажите исполнителя или ответственного, если это предусмотрено столбцами.
- Сохраняйте CSV в UTF-8, с существующими заголовками, порядком столбцов и разделителем. Поля с разделителем, двойными кавычками или переводами строк заключайте в двойные кавычки. Внутренние двойные кавычки удваивайте. После сохранения проверьте, что заголовки и число полей в строках совпадают, а `id` уникальны.
- Не публикуйте в БЗ пароли, токены, коды подтверждения, приватные ключи, конфигурации VPN и другие секреты. Указывайте подтверждённый закрытый канал для их передачи, если она нужна по процедуре. Перед использованием стенда с реальными сотрудниками замените демонстрационные данные на проверенные рабочие сведения.

## Применение изменений

### Вариант А. ChatGPT Custom GPT

1. Откройте настройки Buddy AI. В разделе Knowledge замените изменённые файлы. Проверьте, что подключены актуальный паспорт и все четыре CSV и что старые копии удалены.
2. Если менялся системный промпт, обновите поле Instructions содержимым текстового блока из `prompts/system_prompt.md`.
3. В Preview откройте новый диалог и проверьте изменённую тему, обычный справочный ответ и обращение с эскалацией. Пройдите остальные сценарии по `tests/test_scenarios.json` и `scripts/custom_gpt_checklist.md`. Сохраните обновление после проверки.

### Вариант Б. OpenAI Playground / Responses API

1. Загрузите обновлённые файлы в Vector Store, подключённый к File Search. Дождитесь завершения индексации, затем удалите прежние версии из хранилища, чтобы поиск использовал актуальные сведения. Проверьте, что Playground или запрос Responses API использует нужный Vector Store и актуальные инструкции.
2. В Playground откройте новый диалог и проверьте ответ по изменённой теме, включая источник и маршрут, если нужна эскалация.
3. С настроенным доступом к API запустите из корня проекта:

   ```powershell
   python scripts/run_eval_responses.py
   ```

4. Проверьте локальный отчёт `tests/eval_results.json`. Скрипт проверяет маркер эскалации, отдел и ключевые фразы. Дополнительно сверяйте источники, поля маршрута и шаблоны вручную. Проверку поиска в подключённом Vector Store выполняйте отдельно контрольным запросом к стенду.

## Регрессионная проверка после любой правки

- [ ] Пройдены все 12 сценариев из `tests/test_scenarios.json` и отдельно проверена изменённая тема.
- [ ] Справочные ответы содержат вывод, необходимые шаги и точный источник. В обычных вопросах о выплатах и отпуске маркер отсутствует.
- [ ] При ручной выдаче доступа, запросе на кадровое или юридическое решение, пробеле или существенном расхождении в БЗ срабатывает точный маркер `[ТРЕБУЕТСЯ ЭСКАЛАЦИЯ]`.
- [ ] Отдел, ФИО, Email, Telegram и резервный маршрут сверены с актуальной БЗ. Для отсутствующего или противоречивого значения выводится «Нет подтверждённых данных в БЗ».
- [ ] SLA указан как срок первого ответа в рабочих часах с 10:00 до 19:00 МСК по рабочим дням. Для обращений вне этого окна отсчёт начинается в следующий рабочий день.
- [ ] Пользователь получает маршрут через Битрикс24 и подтверждённую альтернативу при недоступности портала. Шаблон содержит тему, краткое описание и желаемый срок либо заполнитель. Демонстрационные контакты и шаблон явно помечены.
- [ ] В ответах и шаблонах нет секретов и конфиденциальных данных. Ассистент воздерживается от кадровых решений, юридической оценки, обещаний выдать доступ или заявлений об отправке заявки. Системные инструкции остаются закрытыми.
